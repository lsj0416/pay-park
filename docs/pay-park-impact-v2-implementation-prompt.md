# 이번달페이 Impact V2 로컬 구현 프롬프트

아래 내용을 로컬 프로젝트를 연 Codex, Claude Code 등 코딩 에이전트에 그대로 전달한다.

---

## 복사해서 사용할 프롬프트

`pay-park` 프로젝트의 기존 계산·저장 기능을 유지하면서, 사용자가 첫 화면과 결과 화면에서 핵심 가치를 즉시 느낄 수 있도록 UI를 Impact V2로 개선해줘.

### 프로젝트 정보

- 저장소: `https://github.com/lsj0416/pay-park`
- 기술: HTML, CSS, Vanilla JavaScript ES Module
- 빌드 도구와 패키지 설치 없음
- 주요 파일:
  - `index.html`
  - `css/tokens.css`
  - `css/components.css`
  - `css/app.css`
  - `js/app.js`
  - `js/calculator.js`
  - `js/planner.js`
  - `js/store.js`
  - `js/ui.js`
- 디자인 기준: [Figma · 유경 Impact V2](https://www.figma.com/design/9cKrTarHBlS8HlDRF0YZke?node-id=139-2)

### 작업 전 원칙

1. 먼저 현재 브랜치와 변경 파일을 확인하고 사용자의 미커밋 변경을 덮어쓰지 않는다.
2. 별도 지시가 없다면 로컬에서만 수정하고 커밋·푸시는 하지 않는다.
3. React, Tailwind, npm 패키지, 빌드 도구를 새로 도입하지 않는다.
4. `calculateBudget()`, `calculateDailyBudget()`, `buildPlan()`의 기존 계산 규칙을 변경하지 않는다.
5. `localStorage` 키와 `state.version`을 변경하지 않는다. 기존 저장 데이터가 그대로 복원되어야 한다.
6. 화면은 기존 7개 상태를 유지한다. 신규 라우트, 회원가입, 마이페이지, 서버, DB, 외부 AI API를 추가하지 않는다.
7. `data-screen`, `data-action`, `data-field`, 기존 핵심 `data-output` 속성은 가능한 한 유지한다. 추가 출력값이 필요할 때만 새 속성을 추가한다.
8. 금융상품과 AI는 실제 서비스처럼 오해되지 않도록 현재 면책 문구를 유지한다.

## 목표

현재 화면은 계산을 끝내야 서비스의 장점이 보이고, 결과 숫자의 변화도 약하다. 아래 순서로 개선한다.

1. 첫 방문 홈에서 예시 결과를 먼저 보여준다.
2. 계산 결과를 `실수령액 − 고정비 − 저축 = 가용 금액` 구조로 명확히 보여준다.
3. `AI 활용 계획`을 사용자의 언어인 `이거 사도 될까?` 소비 시뮬레이터로 바꾼다.
4. 계획 적용 전후의 하루 예산과 감소액을 가장 강하게 강조한다.
5. 가상 저축상품 목록은 핵심 흐름에서 내려 선택형 보조 영역으로 만든다.
6. 기존 Mobile·Tablet·Desktop 반응형 구조에서 모두 자연스럽게 동작하게 한다.

## 기준 예시 데이터

첫 방문 홈의 샘플 카드에서만 아래 고정 스냅샷을 사용한다. 실제 사용자 계산 결과는 현재 날짜와 입력값을 사용하므로 이 값을 하드코딩하지 않는다.

| 고정비 | 770,000원 |
| 저축 | 500,000원 |
| 가용 금액 | 1,505,870원 |
| 예시 남은 기간 | 28일 |

## 우선순위 1 — 첫 방문 홈

대상: `index.html`의 `[data-screen="home"] [data-home-view="empty"]`

### 변경 내용

- 헤드라인을 다음 방향으로 변경한다.
  - Eyebrow: `3분이면 이번 달 쓸 돈이 보여요`
  - 제목: `월급은 들어왔는데, 얼마까지 써도 될까요?`
  - 설명: `공제·고정비·저축을 빼고 오늘부터 쓸 수 있는 금액을 계산해드려요.`
- 현재 원화 아이콘 중심의 `.home-empty__visual`을 결과 샘플 카드로 교체한다.
- 샘플 카드에서 가장 크게 `오늘 하루 53,781원`을 보여준다.
- 보조 정보로 `이번 달 남은 생활비 1,505,870원`, `실수령 277만원`, `고정비+저축 127만원`을 표시한다.
- CTA를 두 개로 나눈다.
  1. Primary: `예시 결과 먼저 보기`
  2. Secondary: `내 금액으로 계산하기`
- `예시 결과 먼저 보기`는 새 화면을 만들거나 샘플 데이터를 저장하지 않는다. 같은 홈 화면 안에서 샘플 계산 근거를 펼치거나 접는 방식으로 구현한다.
- 샘플 펼침 영역에 다음 네 줄을 표시한다.
  - 예상 실수령액 `+ 2,775,870원`
  - 고정비 `− 770,000원`
  - 저축 `− 500,000원`
  - 가용 금액 `= 1,505,870원`
- 새 액션 이름은 `data-action="toggle-sample-result"`로 사용한다. `aria-expanded`와 펼침 영역의 `hidden`을 함께 갱신한다.
- `내 금액으로 계산하기`는 기존 `start-calculation` 액션을 그대로 사용한다. 작성 중 데이터가 있으면 기존처럼 `이어서 계산하기`로 바뀌어야 한다.
- `로그인·저장 없이 바로 확인할 수 있어요`라는 신뢰 문구를 추가한다.

### 상태 주의사항

- 샘플 펼침 여부는 저장할 필요가 없다. DOM 상태 또는 메모리 변수로만 관리한다.
- 샘플 보기로 `state.result`, `state.plan`, `currentScreen`, localStorage를 변경하지 않는다.

## 우선순위 2 — 계산 결과의 차감 구조

대상: `[data-screen="result"]`, `renderResult()`

### 변경 내용

- 제목을 `이번 달, 진짜 쓸 수 있는 돈`으로 바꾼다.
- 가용 금액 히어로 카드를 첫 번째 핵심 카드로 유지한다.
- 기존 `계산 근거`를 차감 사다리 형태로 강화한다.
  - 예상 실수령액 `+ 금액`
  - 고정비 `− 금액`
  - 저축 `− 금액`
  - 구분선
  - 가용 금액 `= 금액`
- 가용 금액 행을 렌더링하기 위해 `data-output="result-available"`을 추가하고 `renderResult()`에서 값을 채운다.
- 고정비와 저축의 마이너스 값은 위험색으로, 최종 가용 금액은 브랜드색과 굵은 글자로 표시한다.
- 하루 예산은 별도의 브랜드 소프트 컬러 카드로 만들고 `하루 사용 가능 53,781원`처럼 한 행에서 강하게 보여준다.
- 기존 `AI와 활용 계획 세우기` 진입 카드의 문구를 `이 돈으로 소비 계획 세우기`로 바꾼다. 액션 `open-ai-plan`은 유지한다.
- 가용 금액이 0원일 때 현재 경고와 CTA 동작을 유지한다.

## 우선순위 3 — 소비 시뮬레이터

대상: `[data-screen="ai-plan"]`, `renderPlan()`, 기존 `build-plan`/`apply-plan` 액션

### 화면 문구

- 화면 제목: `이거 사도 될까?`
- 설명: `여행, 쇼핑, 비상금이 내 하루 예산을 얼마나 바꾸는지 바로 확인해요.`
- 입력 섹션 제목: `이번 달 특별 지출이나 모으고 싶은 금액을 적어보세요.`
- 실행 버튼: `영향 계산하기`
- 적용 버튼: `내 예산에 반영하기`

### 동작

- 기존 `buildPlan()` 파서를 그대로 사용한다.
- `계획 세우기` 결과를 단순 배분안보다 전후 비교 카드 중심으로 재구성한다.
- 결과 카드의 핵심 출력은 다음 세 값이다.
  - 현재 하루 예산: 기존 `daily.dailyBudget`
  - 반영 후 하루 예산: 기존 `plan.adjustedDailyBudget`
  - 하루 감소액: `Math.max(0, daily.dailyBudget - plan.adjustedDailyBudget)`
- 감소액 표시용 `data-output="budget-decrease"`를 추가하고 `renderPlan()`에서 렌더링한다.
- 전후 값은 `현재 금액 → 반영 후 금액` 순서로 한눈에 보이게 한다.
- 여행·비상금 등 파싱된 목표는 칩 또는 간결한 목록으로 유지한다.
- 계획이 아직 생성되지 않았으면 적용 버튼을 disabled 처리하고, `renderPlan()`에서 상태를 갱신한다.
- 계획 적용 로직과 `state.plan` 구조는 바꾸지 않는다.

### 저축상품 영역

- 기존 상품 목록과 토글, 면책 문구는 삭제하지 않는다.
- `<details>` 또는 접근 가능한 접기/펼치기 버튼 안으로 옮기고 기본 상태를 닫힘으로 둔다.
- 제목은 `저축상품 후보 보기 · 선택` 수준으로 축소한다.
- 상품 목록이 소비 영향 카드보다 먼저 보이거나 더 강한 시각적 강조를 받으면 안 된다.

## 우선순위 4 — 계획 반영 결과

대상: `[data-screen="ai-result"]`, `renderAppliedResult()`

### 변경 내용

- 제목을 `하루 예산이 이렇게 바뀌어요`로 변경한다.
- 가장 큰 히어로 영역에 아래 값을 함께 표시한다.
  - 적용 전 하루 예산
  - 화살표
  - 적용 후 하루 예산
  - `하루 N원 감소`
- 필요한 출력 속성을 추가한다.
  - `data-output="applied-original-daily-budget"`
  - 기존 `data-output="applied-adjusted-daily-budget"`
  - `data-output="applied-budget-decrease"`
  - `data-output="applied-remaining-living"`
  - `data-output="applied-allocations"`
- `renderAppliedResult()`에서 다음을 계산한다.
  - `originalDaily = dailyFor(result.availableAmount, state).dailyBudget`
  - `adjustedDaily = plan.adjustedDailyBudget`
  - `decrease = Math.max(0, originalDaily - adjustedDaily)`
  - 이번 달 남은 생활비는 `plan.remainingLiving`
- 기존 히어로의 `applied-total`은 원래 가용 금액을 강조하는 용도로 사용하지 않는다. 화면에서는 계획을 뺀 `plan.remainingLiving`을 `이번 달 남은 생활비`로 표시한다.
- `renderGoalList()`를 재사용해 여행·비상금과 남은 생활비의 합이 원래 가용 금액과 일치하도록 보여준다.
- `이번 달 계획 안에서 사용할 수 있어요` 안내를 성공색 카드로 표시한다. 단, `remainingLiving === 0`이면 낙관 문구 대신 `계획 금액이 가용 자금을 모두 사용해요`처럼 중립 또는 주의 문구를 사용한다.
- Primary CTA는 `홈에서 매일 확인하기`로 변경하고 기존 `confirm-plan-home` 액션을 유지한다.

## 완료 후 홈 대시보드

- 계획이 없는 경우 기존 하루 예산을 유지한다.
- 계획이 있는 경우 사용자가 실제로 참고할 기본 하루 예산은 조정된 예산이므로, 홈에서 조정된 하루 예산을 더 강하게 표시한다.
- 원래 하루 예산은 `계획 전` 보조 값으로 남긴다.
- 기존 계산 근거, 진행률, 다시 계산하기 기능은 유지한다.

## 반응형 구현

현재 `css/tokens.css`와 `css/app.css`에는 이미 아래 기준이 구현돼 있다.

- Mobile: `~767px`
- Tablet: `768px~1439px`
- Desktop: `1440px 이상`
- Tablet 콘텐츠 최대폭: `640px`
- Desktop 콘텐츠 최대폭: `1200px`
- Desktop 계산 화면: 좌측 StepNav `320px` + 우측 콘텐츠 `720px`

이 구조를 삭제하거나 새로운 breakpoint 체계로 다시 만들지 않는다. 새 컴포넌트만 기존 체계에 맞춘다.

### Mobile

- 320, 375, 390, 430px에서 한 컬럼이다.
- CTA는 기존 sticky 패턴을 유지한다.
- 전후 비교는 작은 화면에서도 `현재 → 반영 후`가 한 행에 들어가도록 하되, 320px에서 숫자가 겹치면 두 줄 그리드로 안전하게 바뀌게 한다.
- 상품 후보는 기본 닫힘이다.

### Tablet

- 768, 1024px에서 콘텐츠 최대폭 640px 중앙 정렬을 유지한다.
- sticky CTA는 기존 구현처럼 정적 버튼으로 바뀐다.
- 결과 카드 안에서는 히어로와 계산 근거 또는 전후 비교를 공간이 허용하면 2열로 배치한다.

### Desktop

- 1440px에서 기존 1200px 콘텐츠 그리드를 유지한다.
- 계산 결과: 좌측 가용 금액·하루 예산, 우측 차감 근거와 CTA.
- 소비 시뮬레이터: 좌측 입력·파싱 목표, 우측 전후 영향과 적용 CTA.
- 계획 반영 결과: 좌측 하루 예산 전후 히어로, 우측 남은 생활비·적용 목표·CTA.
- 상품 후보는 두 번째 열의 핵심 카드가 아니라 하단의 접힌 보조 영역이다.

## CSS 컴포넌트 제안

프로젝트 네이밍 규칙에 맞게 다음과 같은 클래스를 추가하되, 이름은 현재 코드와 충돌하지 않는지 먼저 확인한다.

```text
.sample-result-card
.sample-result-card__metrics
.subtraction-card
.subtraction-row
.subtraction-row--negative
.subtraction-row--total
.daily-budget-highlight
.simulator-impact
.budget-comparison
.budget-comparison__before
.budget-comparison__after
.budget-decrease-badge
.optional-products
.applied-result-hero
.success-message
```

- 색상은 반드시 기존 CSS 변수부터 사용한다.
- 새 색상이 필요하면 `tokens.css`에 의미 기반 토큰을 최소한으로 추가한다.
- 버튼, 카드, 입력창의 기존 컴포넌트 스타일을 최대한 재사용한다.
- focus-visible, disabled, hidden, aria-expanded 상태를 지원한다.
- 애니메이션을 추가한다면 `prefers-reduced-motion`을 존중한다.

## 검증 시나리오

### 기능

1. 저장 데이터가 없는 첫 방문 홈에서 샘플 금액과 두 CTA가 보인다.
2. `예시 결과 먼저 보기`를 누르면 같은 화면에서 근거가 펼쳐지고 localStorage는 변하지 않는다.
3. `내 금액으로 계산하기`를 누르면 기존 S01로 이동한다.
4. 세전 3,200,000원, 고정비 770,000원, 저축 500,000원 입력 결과가 1,505,870원이다.
5. 결과 화면에 네 단계 차감 구조와 동적으로 계산된 하루 예산이 보인다.
6. `여행 30만 원, 비상금 20만 원` 입력 시 두 목표 합계는 500,000원, 남은 생활비는 1,005,870원이다.
7. 소비 시뮬레이터에서 현재·반영 후 하루 예산과 차이가 정확히 표시된다.
8. 적용 전에는 적용 버튼이 비활성이고, 영향 계산 후 활성화된다.
9. 계획 적용 후 결과와 홈에 동일한 조정 하루 예산이 표시된다.
10. 새로고침 후 기존 계산 결과와 계획이 복원된다.
11. 다시 계산하기, 뒤로가기, StepTabs, 입력 항목 추가·삭제가 기존처럼 동작한다.
12. 상품 후보는 기본 닫힘이며 펼쳤을 때 기존 토글·목록·면책 문구가 동작한다.

### 화면과 접근성

- 320, 375, 390, 430, 768, 1024, 1440px에서 가로 스크롤이 없다.
- 모든 주요 숫자가 잘리지 않고 카드 밖으로 넘치지 않는다.
- 키보드만으로 CTA, 샘플 펼침, 상품 펼침, 폼 입력을 사용할 수 있다.
- 토글 버튼의 `aria-expanded`와 대상 영역의 `hidden`이 일치한다.
- 화면 전환 후 적절한 제목으로 포커스를 옮기거나 최소한 페이지 상단으로 이동하는 기존 동작을 유지한다.
- 콘솔 오류와 404 요청이 없다.

## 로컬 실행과 확인

```bash
python3 -m http.server 8080
```

`http://localhost:8080`에서 확인한다. 브라우저 개발자 도구로 위 viewport를 점검하고, localStorage 유지·삭제 두 상태를 모두 검증한다.

## 구현 판단 메모

- 저장소의 반응형 코드는 이미 `css/app.css`에 반영되어 있으므로 이번 작업의 중심은 새 레이아웃 구축이 아니라 Impact V2 컴포넌트의 반응형 확장이다.
- 첫 방문 샘플은 사용자 데이터가 아니므로 저장 상태와 철저히 분리한다.
- 동적 하루 예산은 현재 날짜에 따라 달라진다. 디자인의 `53,781원 → 35,924원`은 28일 기준 설명용 예시일 뿐, 실제 결과 화면에서는 `calculateDailyBudget()` 결과를 사용한다.
- 새로운 기능을 다수 추가하기보다 `입력 전 가치 제시 → 계산 근거 → 소비 영향 → 적용 전후`의 전달 순서를 강화하는 작업이다.
