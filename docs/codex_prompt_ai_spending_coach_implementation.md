# 이번달페이 AI 소비 코치 구현 프롬프트

아래 내용을 그대로 Codex에 전달해 작업해줘.

---

## 작업 목표

`pay-park` 프로젝트에 최신 Figma의 `AI 소비 코치` 화면과 동작을 구현해줘.

기존 `이거 사도 돼?` 기능의 정확한 예산 판정은 유지하고, 판정 결과를 사용자가 실행할 수 있는 소비 조정안으로 바꿔주는 역할을 AI에 추가한다.

- GitHub 저장소: https://github.com/lsj0416/pay-park
- Figma 파일: https://www.figma.com/design/9cKrTarHBlS8HlDRF0YZke?node-id=79-2
- 기준 페이지: `유경`
- 홈 화면: `79:953`
- `사도 돼요` 화면: `165:429`
- `조금 위험해요` 화면: `165:31`
- `예산 초과예요` 화면: `178:135`
- 가용 자금 결과 페이지: `79:367`

## 작업 원칙

1. 먼저 저장소의 프레임워크, 라우팅, 상태 관리, 스타일링, 로컬 저장 구조, AI 연동 유무, 배포 방식을 확인한다.
2. 기존 컴포넌트와 디자인 토큰을 우선 재사용한다.
3. Figma의 색상, 간격, 타이포그래피, 카드 구조를 기준으로 구현한다.
4. 관련 없는 리팩터링과 전역 포맷팅은 하지 않는다.
5. 기존 사용자의 로컬 저장 데이터와 예산 계산 결과를 깨뜨리지 않는다.

## 핵심 설계 원칙

예산 계산과 AI의 책임을 분리한다.

### 계산 엔진이 담당할 것

- 가용 자금
- 현재 하루 예산
- 결제 후 남는 금액
- 결제 반영 후 하루 예산
- 초과 금액
- `SAFE / CAUTION / OVER_BUDGET` 판정

### AI가 담당할 것

- 자연어에서 상품명, 금액, 시점, 목적 추출
- 계산 결과를 이해하기 쉬운 말로 설명
- 사용자의 현재 예산을 바탕으로 실행 가능한 조정안 생성
- 추천안과 대체안 제시

AI가 생성한 숫자를 그대로 신뢰하지 않는다. 화면에 표시되는 모든 금액과 판정은 기존 계산 유틸리티 또는 별도의 순수 함수로 다시 계산한다.

## 우선순위 1 — 홈 진입 카드

홈 화면의 기존 구매 확인 카드를 Figma와 동일한 AI 소비 코치 진입 카드로 변경한다.

- 라벨 및 제목: `✦ AI 소비 코치`
- 설명: `오늘 이거 사도 돼? 결제 전에 바로 물어보세요`
- 연한 브랜드 배경과 브랜드 컬러 테두리를 유지한다.
- 화살표를 포함해 카드 전체를 클릭할 수 있어야 한다.
- 클릭하면 AI 소비 코치 모달을 연다.
- 이 진입 카드는 홈 화면에만 존재해야 한다.
- 가용 자금 결과 페이지의 `AI 활용 계획 세우기` 기능과 혼합하지 않는다.

## 우선순위 2 — 자연어 소비 입력

모달 제목:

```text
✦ AI 소비 코치
```

기존 상품명·가격 입력 방식은 유지할 수 있지만, 하나의 자연어 문장으로 입력할 수 있게 확장한다.

입력 예시:

```text
오늘 치킨 25,000원 먹어도 될까?
닌텐도 칩 60,000원 사도 될까?
맥북 2,000,000원 사도 될까?
```

- 기존 빠른 선택 버튼은 유지한다.
- CTA 문구는 `AI로 확인하기`를 사용한다.
- 자연어에서 추출한 금액은 사용자가 확인하거나 수정할 수 있어야 한다.
- 금액을 추출하지 못하면 임의로 추정하지 말고 금액 입력을 요청한다.
- 0원, 음수, 숫자가 아닌 값은 계산하지 않고 입력 오류를 표시한다.

## 우선순위 3 — 판정 로직 유지

아래 판정 순서를 변경하지 않는다.

```ts
if (paymentAmount > availableFunds) {
  return 'OVER_BUDGET';
}

if (paymentAmount <= dailyBudget) {
  return 'SAFE';
}

return 'CAUTION';
```

| 상태 | 조건 | 화면 문구 |
| --- | --- | --- |
| `OVER_BUDGET` | `결제액 > 가용 자금` | `예산 초과예요` |
| `SAFE` | `결제액 ≤ 하루 예산` | `사도 돼요` |
| `CAUTION` | `하루 예산 < 결제액 ≤ 가용 자금` | `조금 위험해요` |

경계값:

- `결제액 === 가용 자금`은 예산 초과가 아니다.
- `결제액 === 하루 예산`은 `SAFE`다.

## 우선순위 4 — 상태별 AI 제안

판정 카드 안에서 계산 결과를 먼저 보여주고, 그 아래에 AI 코치 영역을 표시한다.

### SAFE — 사도 돼요

표시할 계산값:

- 현재 하루 예산
- 결제 반영 후 하루 예산

AI 코치 예시:

```text
✦ AI 코치
이 결제는 오늘 예산 안이에요. 결제 후에도 하루 53,687원을 쓸 수 있고 이번 달 목표도 유지돼요.
```

CTA:

```text
결제하고 반영하기
```

### CAUTION — 조금 위험해요

표시할 계산값:

- 결제 후 이번 달 남는 돈
- 현재 하루 예산과 결제 후 하루 예산

AI 코치 영역:

```text
✦ AI가 가능한 방법을 찾았어요
```

Figma 예시 선택지:

- 추천: `5일간 하루 416원씩 조정`
- 다른 방법: `구매 금액을 50,000원으로 낮추기`

위 금액을 코드에 고정하지 않는다. 실제 결제액, 하루 예산, 남은 기간으로 계산하거나 AI가 제안한 조정안을 계산 엔진으로 검증한 뒤 표시한다.

기본 분산 조정 계산:

```ts
const excessAmount = paymentAmount - dailyBudget;
const adjustmentDays = Math.max(1, Math.min(5, remainingDays));
const savingPerDay = Math.ceil(excessAmount / adjustmentDays);
```

CTA:

```text
이 계획으로 반영하기
```

선택한 조정안이 현재 예산 상태 또는 기존 로컬 저장 구조에 반영되어야 한다.

### OVER_BUDGET — 예산 초과예요

표시할 계산값:

- 결제 후 이번 달 남는 돈
- 현재 가용 자금
- 초과 금액

AI 코치 영역:

```text
✦ AI가 대안을 찾았어요
```

제안 예시:

- 추천: `다음 달 구매 계획 만들기`
- 다른 방법: `현재 가능한 최대 금액 확인하기`

메인 CTA는 기존 정책대로 유지한다.

```text
결제하지 않기
```

예산 초과 상태에서는 결제 금액을 예산에 반영하지 않는다.

## AI 응답 구조

AI 연동이 존재한다면 자유 형식의 긴 문장보다 검증 가능한 구조화 응답을 사용한다.

예시 타입:

```ts
type AiSpendingCoachResponse = {
  parsedInput?: {
    itemName?: string;
    amount?: number;
    plannedDate?: string;
    purpose?: string;
  };
  explanation: string;
  recommendedOption?: {
    id: string;
    title: string;
    description?: string;
    adjustmentAmount?: number;
    adjustmentDays?: number;
  };
  alternatives: Array<{
    id: string;
    title: string;
    description?: string;
    adjustmentAmount?: number;
    adjustmentDays?: number;
  }>;
};
```

- 런타임 검증 스키마가 이미 있으면 재사용한다.
- AI의 판정값은 사용하지 않는다. 판정은 계산 엔진이 확정한다.
- AI가 제시한 금액이 현재 예산과 맞지 않으면 폐기하고 검증된 기본 조정안을 보여준다.
- 설명은 짧게 제한하고 카드 내부에서 잘리지 않게 한다.

## AI 연동 및 보안

1. 기존 AI provider 또는 API route가 있으면 그대로 재사용한다.
2. API 키를 브라우저 코드, `NEXT_PUBLIC_*`, 저장소에 포함하지 않는다.
3. 서버 실행이 가능한 구조라면 서버 API route 또는 기존 서버 계층에서 호출한다.
4. Netlify 정적 배포 구조라면 클라이언트에 키를 넣지 않는다. 기존 Netlify Function이 있으면 재사용하고, 없다면 새로운 서버 구조를 임의로 확장하지 말고 작업을 멈춘 뒤 확인을 요청한다.
5. 사용자의 급여와 예산 데이터를 불필요하게 로그로 남기지 않는다.
6. 요청 타임아웃과 실패 처리를 추가한다.

AI 호출이 실패해도 계산 결과는 정상적으로 보여야 한다.

```text
예산 계산은 완료했지만 AI 제안을 불러오지 못했어요.
기본 조정안을 확인하거나 다시 시도해 주세요.
```

실패 시 AI가 만든 것처럼 위장하지 말고 `기본 조정안`이라고 표시한다.

## 상태 및 저장

- 기존 가용 자금, 하루 예산, 남은 기간 데이터를 재사용한다.
- AI 소비 코치 전용 전역 상태를 불필요하게 만들지 않는다.
- 모달 안에서만 사용하는 입력·로딩·결과 상태는 가능한 한 로컬 상태로 관리한다.
- 사용자가 조정안을 확정한 경우에만 기존 예산 또는 로컬 저장 데이터에 반영한다.
- 모달을 닫거나 `결제하지 않기`를 선택하면 예산을 변경하지 않는다.
- 중복 클릭으로 같은 결제가 두 번 반영되지 않도록 방지한다.

## 모달 상호작용 및 접근성

- 모바일에서는 Figma와 같은 바텀시트 형태를 사용한다.
- 태블릿·데스크톱에서는 중앙 정렬 다이얼로그로 표시한다.
- 닫기 버튼, 바깥 영역 클릭, `Escape` 키를 지원한다.
- 모달이 열리면 배경 스크롤을 막는다.
- 열릴 때 입력창으로 포커스를 이동한다.
- 닫힐 때 홈의 AI 소비 코치 카드로 포커스를 되돌린다.
- 선택지는 키보드로 선택할 수 있어야 한다.
- 로딩 중에는 CTA를 비활성화하고 중복 요청을 막는다.
- 작은 화면에서 내용이 잘리지 않도록 모달 내부 세로 스크롤을 허용한다.

## 반응형 기준

기존 브레이크포인트가 있으면 우선 사용한다. 없다면 다음 기준을 적용한다.

| 구간 | 기준 | AI 소비 코치 UI |
| --- | --- | --- |
| 모바일 | `0~767px` | 전체 너비 바텀시트, 하단 CTA 고정 |
| 태블릿 | `768~1199px` | 최대 너비 약 560px의 중앙 다이얼로그 |
| 데스크톱 | `1200px 이상` | 최대 너비 약 600px의 중앙 다이얼로그 |

- 375px, 768px, 1440px에서 확인한다.
- 가로 스크롤과 화면 밖으로 잘리는 텍스트가 없어야 한다.
- 최소 클릭 영역은 약 44px을 확보한다.

## 테스트

가능한 범위에서 다음을 검증한다.

### 단위 테스트

- `paymentAmount > availableFunds` → `OVER_BUDGET`
- `paymentAmount === availableFunds` → `OVER_BUDGET` 아님
- `paymentAmount === dailyBudget` → `SAFE`
- `dailyBudget < paymentAmount < availableFunds` → `CAUTION`
- 조정 일수와 일일 절약 금액 계산
- AI 응답 스키마 검증
- 잘못된 AI 금액을 폐기하고 기본 계산값을 사용하는지 확인

### UI 테스트

- 홈 카드 클릭 시 모달 열림
- 자연어 입력 후 로딩 및 결과 표시
- 세 상태별 AI 영역 표시
- 조정안 선택과 예산 반영
- 결제하지 않기 선택 시 예산 미변경
- AI 호출 실패 시 계산 결과와 기본 조정안 유지
- 모달 닫기와 포커스 복귀

### 프로젝트 검증

- lint
- type-check
- test
- build

프로젝트에 존재하는 명령만 실행한다.

## 작업 범위 제한

- 로컬 코드 수정까지만 수행한다.
- 브랜치 생성, 커밋, 푸시, PR, 배포는 하지 않는다.
- 새로운 백엔드나 인증 기능을 임의로 만들지 않는다.
- 새로운 패키지는 꼭 필요한 경우에만 추가한다.
- 가용 자금 결과 페이지의 `AI 활용 계획 세우기` 기능은 AI 소비 코치와 분리해서 유지한다.
- 저축상품 추천 기능은 이번 작업 범위에서 새로 추가하지 않는다.
