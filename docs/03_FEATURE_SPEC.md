# 화면별 기능 명세

> Figma `유경` 페이지의 7개 프레임(예산 기간 설정/소득 입력/고정비, 저축/결과/AI 활용 계획 및 추천 상품/AI 반영/홈화면)을 MCP로 직접 조회해 실제 문구·구조·동작으로 갱신했다. 화면 개수는 7개로 그대로 유지했다.

## S07 홈

Figma 노드: `홈화면`(79:953). 하단에 `BottomNav`(홈/마이 2탭)가 실제로 존재한다. "마이" 탭은 클릭해도 아무 동작을 하지 않거나(비활성) 준비 중 안내만 하고, 별도 마이페이지 화면은 만들지 않는다(범위 밖 정책 유지).

### 첫 방문·작성 중

- 서비스 설명: `세금·저축까지 빼고, 이번 달 진짜 쓸 수 있는 돈을 확인해보세요.`
- 저장된 입력이 없으면 CTA는 `내 가용 자금 계산하기`다.
- 미완료 입력이 있으면 CTA는 `이어서 계산하기`이며 마지막 완료 다음 단계로 이동한다.

### 완료 결과 대시보드

Figma 실측 문구·구조:

- 상단: 예산 기간(`8월 10일 – 9월 9일`) + 2줄 타이틀(`이번 달` / `진짜 쓸 수 있는 돈이에요`). **Figma에는 "유경님,"이라는 이름이 붙어 있으나, 이 프로토타입은 로그인·계정이 없으므로 특정 이름을 하드코딩하지 않는다.** 이름 자리는 생략하고 `이번 달 진짜 쓸 수 있는 돈이에요`처럼 이름 없는 문장으로 대체한다.
- `HeroCard`(브랜드색 배경): 대표 가용 자금 금액(`renderMoney(availableAmount)`), 2열 미니 통계(`하루 예산` / `남은 기간`), 진행바(진행률 = `availableAmount / estimatedTakeHome`), 보조 설명 `실수령액 중 {percent}%를 자유롭게 쓸 수 있어요`.
- `계산 근거` 카드(흰 배경): `예상 실수령액`, `− 고정지출`, `− 저축·투자`, `= 가용 자금` 4줄.
- CTA 버튼 1개: `이번 달 다시 계산하기` → 저장값을 초기화하지 않고 S01에 기존 값을 채운 상태로 연다. (이전 버전에 있던 `결과 자세히 보기` 버튼은 Figma에 없으므로 만들지 않는다. 결과를 다시 자세히 보고 싶으면 아래 "계산 근거" 카드 자체가 그 역할을 겸한다.)
- 하단 안내: `세금·공제는 근사 계산이며 실제 급여명세서와 다를 수 있어요.`
- `plan`이 저장되어 있으면(AI 계획 적용 상태) `조정된 하루 예산`과 목표별 배분 요약을 이 카드 안에 추가로 보여준다(S06과 같은 정보를 홈에서도 요약 노출).

## S01 예산 기간 설정

Figma 노드: `예산 기간 설정`(79:3).

### 입력

- 월급일: `PAYDAY_PRESETS`(1, 5, 10, 15, 20, 25, 27, 30) 중 하나를 칩으로 선택. 자유 숫자 입력(스피너)이 아니다.
- 기본 선택값: 10일.

### 출력

- 안내 문구: `월급일을 기준으로 이번 달 예산 기간을 정해요.`
- 카드 2장: 위쪽은 월급일 선택 칩(가로 스크롤), 아래쪽은 `이번 달 예산 기간` 결과 카드 — `{시작일} – {종료일} · {총 일수}일` 형식(예: `8월 10일 – 9월 9일 · 31일`).

### 동작

- 월급일 선택 시 예산 기간 미리보기를 즉시 갱신한다.
- 헤더에 `BackButton`(←)이 있다 — 눌러도 이전 화면(홈)이 없는 첫 단계이므로 홈으로 이동한다.
- `다음` 클릭 시 저장 후 S02로 이동한다.
- 월말에 존재하지 않는 날짜(30일 선택 + 2월 등)는 해당 월의 마지막 날로 보정한다.

## S02 소득 입력

Figma 노드: `소득 입력`(79:100).

### 입력

- `입력 기준` 세그먼트 토글: `세전 월급`(기본 선택) / `실수령액`. 실수령액을 선택하면 사용자가 실수령액을 직접 입력하고, 아래 공제 내역 카드는 표시하지 않는다.
- 금액 입력 필드 1개(선택한 기준에 맞는 금액). **이전 버전에 있던 "추가 소득" 입력은 Figma 디자인에 없으므로 제거한다.**

### 출력(세전 월급 기준일 때)

- `예상 실수령액` 카드: `calculateBudget()`으로 계산한 `estimatedTakeHome`.
- 공제 내역 2줄: `4대보험 −{insuranceDeduction}원`, `소득세 · 지방소득세 −{taxDeduction}원`.
- 안내 문구: `추정치 · 실제와 차이가 있을 수 있어요.`(이전 버전 문구 `추정치이며 실제 급여명세와 다를 수 있어요.`에서 표현이 바뀜)

### 동작

- 헤더에 `BackButton`(←) — S01로 이동, 입력값 유지.
- 금액이 0이면 다음으로 이동할 수 없다.
- 저장 후 S03으로 이동한다.

## S03 고정비·저축

Figma 노드: `고정비, 저축`(79:207).

### 입력

두 개의 `ItemListInput` 카드.

- `고정비` 카드: 항목별 이름+금액 리스트(예시: 월세 700,000 / 통신비 50,000 / 구독료 20,000). 프리셋 칩: `관리비`, `보험료`. `+ 직접 추가`로 커스텀 항목 추가.
- `기존 저축·투자` 카드: 항목별 이름+금액 리스트(예시: 적금 500,000). 프리셋 칩: `주식 정기매수`, `연금`, `ISA`. `+ 직접 추가` 가능.
- **이전 버전의 "고정비 총액 하나만 입력"은 Figma와 다르므로 폐기한다.**

### 출력

- 각 카드 헤더에 해당 카드의 합계(`− {합계}원`).
- 요약 카드: `미리 빠지는 돈` — `총 {고정비합+저축합}원`.
- 이전 버전에 있던 "예상 가용 자금 실시간 미리보기"는 이 화면에 없다(가용 자금 자체는 S04에서 처음 보여준다).

### 동작

- 헤더 `BackButton`(←) — S02로 이동, 입력값 유지.
- 합계가 예상 실수령액을 초과해도 입력은 허용한다.
- 초과 시 계산 결과(S04)는 0원으로 제한하고 `고정비와 저축이 예상 실수령액보다 커요.`를 표시한다(경고는 S04에서 노출).
- 버튼 라벨은 `가용 자금 계산하기`(이전 버전 `결과 보기`에서 변경). 클릭 시 결과 스냅샷을 저장하고 S04로 이동한다.

## S04 가용 자금 결과

Figma 노드: `결과`(79:367). 이 화면은 AI 계획을 아직 적용하지 않은 기본 상태다. AI 계획을 적용한 뒤에는 같은 정보 구조를 가진 S06(AI 반영)으로 대체되어 보인다 — 코드상으로는 `data-screen="result"`와 `data-screen="ai-result"` 두 section을 유지하되, `state.plan` 유무로 어느 쪽을 보여줄지 판단한다.

### 출력

- 안내 문구: `이번 달에 실제로 쓸 수 있는 돈이에요.`
- `HeroCard`: `이번 달 진짜 가용 자금` + `{availableAmount}원`.
- `하루 예산` 카드: `{dailyBudget}원 · {remainingDays}일 기준`.
- `계산 근거` 카드: `실수령 {estimatedTakeHome} − 고정비 {fixedExpenses} − 저축 {savingCommitment}`.
- `AI와 활용 계획 세우기` 링크형 카드: `남은 돈을 목표에 맞게 나눠볼까요?` 문구 + 화살표 아이콘. 클릭 시 S05로 이동.
- `availableAmount`가 0원이면 경고 문구 `고정비와 저축이 예상 실수령액보다 커요.`를 계산 근거 카드 위나 아래에 노출한다.

### 행동

- 헤더 `BackButton`(←) — S03으로 이동, 입력값 유지(이전 버전의 "입력 수정하기" 버튼 역할을 겸한다. 완료된 StepTabs를 눌러 S01·S02로 가는 것도 가능).
- `AI와 활용 계획 세우기` 카드 클릭 → S05.
- 하단 고정 버튼 `완료`(이전 버전의 "AI로 활용 계획 세우기"/"입력 수정하기"/"홈에서 보기" 3버튼 구성은 Figma에 없다) → S07 홈으로 이동.

## S05 AI 활용 계획 및 추천 상품

Figma 노드: `AI 활용 계획 및 추천 상품`(79:467). 세로로 긴 한 화면 안에서 입력 → 배분안 → 상품 후보를 순서대로 보여준다(화면 분리 없음, 유지).

### 입력

- 상단에 `이번 달 가용 자금` 요약 카드(금액 + `현재 하루 예산 {dailyBudget}원 · {remainingDays}일`).
- 질문: `이번 달 특별 지출이나 모으고 싶은 목표가 있나요?`
- `Textarea`, placeholder: `예) 이번 달 말에 여행 30만 원, 비상금 20만 원을 모으고 싶어요.`
- 버튼 2개: `계획 세우기`(주 버튼, pill) / `예시`(보조 버튼, placeholder 문구를 textarea에 채워준다).
- **이전 버전의 "빠른 선택 칩(비상금/여행/목돈/장기 저축)"은 Figma에 없으므로 구현하지 않는다.**

### 출력

`계획 세우기` 클릭 시 `buildPlan(goalText, availableAmount)` 결과를 아래처럼 보여준다.

- `배분안` 카드: `goals` 배열을 라벨+금액 리스트로 나열(예: `여행 준비금 300,000원`, `추가 비상금 200,000원`), 마지막 줄에 `남은 생활비 {remainingLiving}원`. 하단에 `조정된 하루 예산 {adjustedDailyBudget}원`을 기존 하루 예산(`{dailyBudget}원`, 취소선)과 함께 `~에서 조정` 문구로 표시.
- **이전 버전의 "목적 해석 한 문장" 출력은 Figma에 없으므로 만들지 않는다.** `buildPlan()`이 내부적으로 계산하는 `category`는 상품 필터링에만 쓴다.
- `저축상품 후보` 카드: 안내 문구 `월 {목표합계}원 목표에 맞춰 골라봤어요.`, 토글 `급할 때 꺼내 쓸 수 있어야 해요`(켜면 `instantWithdraw` 상품을 우선 정렬), 상품 리스트 아이템 3개(은행명 · 유형 · 기간, 금리 `연 {rate*100}%`, 있으면 보조문구). 하단 안내: `금리 기준일 2026-08-01 · 가입 전 실제 조건을 꼭 확인하세요.`

### 상품 예시 데이터

`01_DATA_STATE_CALCULATION.md`의 `products` 참고(토닥 파킹통장/6개월 단기적금/자유적금 12M, 은행명·금리 포함). 실제 은행이 아닌 가상의 이름이며, "가입 전 실제 조건을 꼭 확인하세요" 안내로 프로토타입임을 명확히 한다.

### 행동

- 헤더 `BackButton`(←) → S04.
- `계획 반영하고 결과로 돌아가기`(하단 고정 버튼, 이전 버전 `이 계획 적용하기`에서 문구 변경) → 계획 저장 후 S06으로 이동.
- `예시` 버튼은 이동이 아니라 입력창에 예시 문구를 채운다(이전 버전의 "다시 입력하기" 역할과는 다르다 — 다시 입력하기 별도 버튼은 없다).

## S06 AI 반영

Figma 노드: `AI 반영`(79:629). **이전 버전 문서는 이 화면을 "목적별 배분 합계·선택한 목표·적용 시각을 보여주는 별도 요약 화면"으로 정의했으나, Figma 실측 결과 이 화면은 S04(결과)와 거의 동일한 레이아웃에 "AI 계획 적용됨" 배지가 추가된 상태다. 아래 명세로 전면 교체한다.**

### 출력

- S04와 동일한 헤더 + StepTabs(4단계 모두 완료 상태) + 안내 문구 `이번 달에 실제로 쓸 수 있는 돈이에요.`
- `HeroCard`: `이번 달 진짜 가용 자금` + `{availableAmount}원`(총액은 AI 계획 적용 여부와 무관하게 동일).
- `하루 예산` 카드: `{dailyBudget}원 · {remainingDays}일 기준`.
- `계산 근거` 카드: S04와 동일.
- `AI 계획 적용됨` 배지 카드: `조정된 하루 예산 {adjustedDailyBudget}원`.
- `AI 활용 계획 다시 보기` 링크형 카드: `남은 돈을 목표에 맞게 나눠볼까요?` 문구, 클릭 시 S05로 이동하며 기존 `goalText`를 textarea에 채운 채 연다.

### 행동

- 헤더 `BackButton`(←) → S05(계획 수정 화면으로 돌아가기).
- `AI 활용 계획 다시 보기` 카드 클릭 → S05, 기존 목적 문장 유지.
- 하단 고정 버튼 `홈으로` → S07.

## 오류·빈 상태

- 저장 데이터 손상 또는 `version` 불일치: 초기 상태로 복구하고 홈 안내 화면 표시.
- 가용 자금 0원: S04에서 경고 문구를 보여주되 `AI와 활용 계획 세우기` 진입은 막지 않는다.
- 목적 미입력 또는 금액을 특정할 수 없는 문장: `buildPlan()`이 목표 자금 30% 기본값으로 폴백한다(`01_DATA_STATE_CALCULATION.md` 참고). 5자 미만 등 별도의 문자 수 검증은 하지 않는다(Figma에 그런 제약 표시가 없음).
- 상품 후보: 항상 `products` 3개를 모두 보여주며, 토글 상태에 따라 정렬만 바뀐다("후보 없음" 상태는 없음).
